# Ovid Core (shared)

The code that Ovid Core // CS, WLR, GT, GS and RS share. Each app's pipeline sources these files first, then its own `R/` folder.
A fix made here reaches all five apps; nothing here knows about Campbell, water level, ground temperature, ERT or drone data.

## Where the apps look for it

1. the folder in the `OVID_CORE` environment variable, if set;
2. `core/` inside the app folder (what `Make_Portable.bat` puts there, so a zipped copy runs anywhere);
3. `../core` beside the app folder (the Ovid_Apps bundle);
4. `~/Desktop/Ovid` (where the core files used to be; a last fallback for older set-ups).

## Files

| File | What it holds |
|---|---|
| `util.R` | console output (`say`, coloured by the app's `PAL`), text clean-up, file-safe names, `read_lines_any`, time helpers (`BASE_OFFSET`, `to_base`, `parse_offset`, `parse_dt` with the app's `DT_FORMATS`, `parse_date_cell(x, end)` for set-up table cells one by one (YYYY-MM-DD with or without a time, M/D/YYYY as Excel saves it, an Excel serial; core 1.11.1: an end date with no time covers the whole day), `step_of`, `fmt_step`, `water_year`) |
| `audit.R` | the audit trail: `audit_schema()` (set once by each app), `audit_reset`, `audit_add`, `audit_flush`, `remove_rows`, `remove_cells`, `problem` |
| `file_audit.R` | every raw file accounted for: `file_reconcile` (per file: read = in output + dropped, with the reasons, values removed and what happened), `file_reconcile_by` (adds files up to a download or logger), `file_reconcile_check`, `audit_by_file` |
| `cache.R` | reusing work between runs: `hash_of`, `code_hash` (the code fingerprint; the screen-only files in `CORE_UI_FILES` are left out, so interface changes redo nothing), `cache_read`, `cache_write`, `cache_prune` (drops what a run did not use), `cache_forget` ("rescan this file"), `key_rows` and `key_cfg` (set-up rows and settings as a key, by value). Results live in `<project>/cache/`; deleting that folder only makes the next run a full one. Per-step code fingerprints: `code_fingerprint()`, `code_names()`; `core_shadows()` lists app functions that replace a core one. |
| `timezones.R` | the time-zone table (`config/timezones.csv`): `TZ_COLS`, `zone_for` (which zone a file's clock was in, by serial, model, path pattern and date span; the app says whether a zone stated in the file wins), `tz_match`, `tz_rows_for` (the rows that can apply to a logger's files, for a cache key), `tz_check` for the set-up check |
| `timestamps.R` | corrupt timestamps among good records (core 1.11.0): `stray_records(t, file, ord)` flags records that are off the time grid and out of the order their file was written in, so a logger that wrote junk dates in January between good December and March data loses only the junk; `in_sequence`, `STRAY_REASON`. Used by CS, WLR and GT stitching (CFG `drop_stray_records`) |
| `report.R` | reports written once and rendered as HTML, PDF or both: build a report from blocks (`rpt_doc`, `rpt_heading`, `rpt_text`, `rpt_cards`, `rpt_table`, `rpt_plot`), then `report_write(doc, base, formats, pal)`; `REPORT_FORMATS` for the HTML / PDF choice; `html_table`. Uses the app's theme; PDF pages are 11 x 8.5 in |
| `neighbours.R` | comparing one site with the others that measure the same thing, from daily means: `neighbour_days` (each day against the median of the other sites, allowing for an offset that drifts with the season and for timing differences while everything warms or cools fast), `neighbour_periods`, `neighbour_summary` (days departing, and whether the site moves with the others at all). Used by GT's between-site check |
| `config.R` | set-up tables: `read_cfg`, `ensure_cols`, `load_configs` and `cfg_path` (for apps with a `CONFIG_FILES` list), `write_cfg` with a backup of every change in `config/history/`, and import / export of a whole configuration. Core 1.12.0: `apply_config_import(..., mode = "update", by = )` replaces the rows the import has for a key (a logger, a station) and keeps the rest; `config_after` gives the table as it would be, for a preview. The review decisions (`config/review_decisions.csv`, written by the Workbench's review queue and Check the data): `wb_queue_id`, `review_read`, `review_write`, `review_decision`, `review_open` for the screens, and for the runs `review_accept` (flags.csv's `accepted` column) and `review_unmark` (accepted flags out of the values' flag columns) |
| `manifest.R` | `CORE_VERSION`, `file_md5`, `write_run_manifest` (run_manifest.csv and run_history.csv); the run log (`run_logged()`, `output/logs/`), error references (`error_ref()`), the app error log (`log_app_errors()`) and the troubleshooting zip (`troubleshooting_zip()`) |
| `preflight.R` | the set-up check's collector (`check_collector`), cell tests (`bad_regex`, `bad_number`, `bad_date`), `check_folders`, `check_status` |
| `qc.R` | the mechanics of quality checks shared by CS, WLR, GT and GS (core 1.13.0; rule ids and the common flags table 1.14.0): `qc_runs` (one flag line per run), `qc_spike_idx` (a value that jumps and comes back, with an optional threshold that follows the sensor's usual step), `qc_flat_idx` (stuck values, with a minimum run, a zero-exempt band and a choice of how gaps count), `qc_step_idx` (a change faster than a rate per hour), `qc_cond_runs_idx` (a condition that lasts a given time); and the WMO quality control codes of BUFR table 0 33 020 (`WMO_QC`, `qc_wmo_register`, `qc_wmo_class`, `qc_wmo_combine`, `qc_wmo_worst`; [codes.wmo.int/bufr4/codeflag/0-33-020](https://codes.wmo.int/bufr4/codeflag/0-33-020)). Rule tables, flag names, thresholds and data-specific checks stay in each app; `qc_spike_idx(confirm =)` and `qc_step_idx(min_hours =)` (1.14.0, off by default), `qc_rule_ids` / `qc_read_rules` (a lasting `rule_id` for each row of a rule table; a `CONFIG_FILES` entry opts in with `rule_ids = "Q"`), `qc_flags_table` (every `flags.csv` ends with `rule_id`, `qc_code`, `app`, `run_id`) |
| `theme.R` | the vim colour schemes (olive-crt for CS, Nord for WLR, soviet for GT, kanagawa for GS, accent for RS), `mix_col`, and `theme_ovid(palette)` with `scale_colour_ovid` / `scale_fill_ovid` for every plot; `param_colours` (each measurement in the colour of what it measures: temperature red, humidity green, precipitation and water blue, wind purple, sunlight yellow, battery grey); `distinct_cols` (core 1.11.0), which keeps colours shown together apart with normal vision and with red-green and blue-yellow colour blindness (`cvd_simulate`) by shifting later ones lighter or darker; and the contrast helpers `contrast_ratio`, `legible` and `legible_css` that keep text at 4.5:1 and plot lines at 3:1 |
| `shell.R` | the shared app shell (core 1.9.0): `ovid_page()` gives every app the same top bar (the app's icon and "ovid // <app>", which also sets the browser tab icon (`ovid_icon`, shell 1.1.0), context bar, run state, main action, Help, Settings), a narrow navigation rail that collapses to icons, and a full-width workspace. Helpers for tool pages: `ovid_head` (title + About popover), `ovid_controls` (main inputs in one row, the rest in an Options popover), `ovid_focus` (fullscreen, Esc to leave), `ovid_split` (optional side-by-side view), overview cards, and one QA/QC look (`ovid_status`, `ovid_flag`, `ovid_notice`, `ovid_review`, `ovid_dt_levels`). Colours come from the app's own palette. All five apps use it |
| `workbench.R` | the Workbench interface (preview, core Unreleased), opt-in beside the Standard shell: `wb_page()` lays out a title bar (app icon, project, a Standard \| Workbench switch, Import / Run / Export), a tree, the main pane, an inspector and a status bar; `wb_wanted()` picks the interface for a request from `?ui=`, then `OVID_UI`, then the app's `ui` setting (Standard by default); `wb_row`, `wb_tab`, `wb_sec`, `wb_fact`, `wb_kv`, `wb_step` and `wb_state` build the panes; `wb_grid()` is the spreadsheet (cell, record and parameter selection, sent back as runs of rows per column), `WB_CHART_JS` the time chart drawn in the browser (zoom, pan, select) and `WB_XY_JS` the point chart for records that are not a time series (`wb_xy_ui()`, `wb_xy_message()`); `wb_data_ui()`, `wb_chart_server()`, `wb_chart_data()`, `wb_grid_cells()` and the rest build an app's data view, `wb_tools_tree()`, `wb_tabs_server()`, `wb_setup_tree()` and `wb_watch_outputs()` its frame. An app's Standard pages can sit in the main pane (tab set `nav`), so `ovid_go()` works there. Colours come from the app's palette; `theme =` takes a bslib theme. Used by every app (`<app>/workbench/`) |
| `periods.R` | corrections over a period (`config/period_corrections.csv`): remove, offset, scale, linear drift, fill by interpolation or flag a target's parameters between two dates; `period_read`, `period_apply`, `period_step` (a run's step, with the audit trail and flags), `period_for` (rows for a cache key). Sourced by the CS, WLR and GT pipelines; the Workbench's Correct a period writes the rows |
| `logger_files.R` | raw logger files, for the processors (CS, GT, WLR): listing the raw folders (`raw_file_list()`, system and lock files left out), checksums reused while a file is unchanged (`file_known()`, `raw_md5()`, `file_known_drop()` for Rescan), byte-identical copies (`copy_of()`), gaps in a record (`gap_rows()`), and the headers of formats more than one app reads: HOBOware CSV (`hobo_csv_head()`), the .hobo binary's identity (`hobo_bin_identity()`) and Campbell TOA5 (`toa5_head()`). What the columns mean stays in each app's reader |
| `deployments.R` | the shared deployment sheet (`config/deployment_sheet.csv`, template in `templates/`): reading and checking it (`dep_sheet()`, `dep_clean()`), deployments the files suggest (`dep_propose()`), matching rows to them (`dep_match()`, `dep_check()`), merging new rows (`dep_merge()`); each processor turns its rows into its own logger list |
| `table_rules.R` | each set-up table's rules (automatic from column names, plus an app's `rules` in CONFIG_FILES): `table_check()`, `declared_checks()`, `with_declared()` for the set-up check, `table_findings()` for the editor |
| guardrails | in `manifest.R` (`run_project()`, `project_check()`, `project_lock()`, `files_locked()`, `run_incomplete()`, `files_gone_check()`, `output_keep()` / `output_restore()` / `output_recover()`, `disk_check()`, `cloud_notes()`), `util.R` (`settings_read()`, `settings_save()`, `parse_dt()`), `config.R` (`read_cfg()` on damaged tables, `fwrite_safe()`), `cache.R` (`saveRDS_safe()`, `cache_load()`, `cache_retry()`): the checks before every run and the safe reads and writes during it. A check that fails stops the run before anything is written and never changes a setting; a run that fails or is cancelled puts back the output the last finished run left |
| `projects.R` | the Projects list (`projects_ui()` / `projects_server()`): new, open (each project's own folders and settings in `config/project_settings.json`), delete outputs or the whole project to the Trash (`project_delete()`, `to_trash()`), remove from the list |
| `rename.R` | renaming a site or station in every set-up table that holds it (`rename_plan()`, `rename_apply()`, `rename_undo()`; the panel `rename_ui()` / `rename_server()`); each app's `RENAMES` says where its names are; the core tables every app has (`RENAME_COMMON`: corrections over a period, calibration options, what shows) and the review decisions follow too |
| `report_options.R` | the Report layout panel and what it sets: titles and file names, a line under the title, the author, sections (`report_wants()`), and axes shared between reports (`axis_limits()`) |
| `corrections.R` | the Automatic corrections list: each processor's `CORRECTIONS` (what it does, removes / changes / fills / flags, the setting or set-up table behind it), shown with its state on the set-up flow's Automatic corrections step (Corrections) (`corrections_ui()` / `corrections_server()`), switches for settings with no other control (`corrections_cfg()`), and the list in every run log (`corrections_log()`) |
| `runner.R` | runs from the app in a background R process (`run_start()`, `run_server()`, callr): a progress box in the corner of both interfaces (stage, item, time) with Cancel, and the Run buttons turned off in every window while a run goes; one run at a time per app. Cancel stops the run at its next message or item (`run_check_cancel()`, `run_tick()` in `util.R`), never in the middle of writing a file. `OVID_RUN_SYNC=1` runs in the app's own process (the tests). CS, GT, WLR, ERT and RS use it; screen-only, like `shell.R` |
| `testkit.R` | reader tests on real sample files (`make_reader_samples()`, `check_reader_samples()`); used by the apps' tests only |
| `uitest.R` | click-through tests in a real browser (`ui_click_through()`, chromote): every page of the rail and the Workbench; used by the apps' tests only |
| `standards.R` | processing levels L0 to L4 (`PROC_LEVELS`, `proc_level()`), the WMO quality codes as CF flag attributes (`cf_qc_atts()`), and a base-R NetCDF writer for CF-1.10 / ACDD-1.3 exports (`nc_write()`, `nc_read()`, `acdd_atts()`, `nc_time()`, `nc_station_vars()`) |
| `metasheet.R` | the metadata sheet (`config/metadata.csv`): an optional table of what people know about loggers, surveys or flights, with the columns each app can use (`META_FIELDS`) and each project's own (`config/metadata_fields.csv`); `meta_sheet()` gives an app the typed rows, `meta_values()` reads values by type, `meta_guess()` / `meta_from_import()` / `meta_merge()` take in a spreadsheet. Nothing in it is required |
| `import.R` | bringing in a table people already have: `meta_import_read` / `meta_import_text` (any CSV, text or Excel file; encodings, separators, heading row), `imp_guess` (matching columns to fields, with how sure), `imp_prepare` and `imp_check` (dates, numbers, choices put in order; errors, warnings and notes before anything is written), `import_spec_guess` (types for tables that declare none) and the matches kept per project (`config/import_memory.csv`). Tests: `core/tests/test_import.R`. |
| `metasheet_ui.R` | the metadata sheet's screen (`meta_sheet_ui`, `meta_sheet_server`: rows from what was found, Paste, Import with column matching, Columns to relabel, hide or add) and `table_import_server()`, the Paste and Import dialogs of every table editor. Screen-only |
| `templates/` | `metadata_template.csv` (blank) and `metadata_example.csv`: the starting metadata sheet, one row per deployment (a serial at a station for a period). Only Serial number is required; blank From/To cover the logger's whole record; a redeployed logger gets a second row |
| `editor.R` | the set-up table editor of every app (`ovid_edit_ui`, `ovid_edit_server`): edit, add, duplicate, delete and save rows with a backup of every change; the same table open in both interfaces or in several windows stays one table (`file_stamp`: a copy with no unsaved edits takes up a newer saved version, one with unsaved edits asks first); `append`, `mutate` and `replace` for corrections made from code. Screen-only, like `shell.R` |
| `sheet.R` | the Workbench's spreadsheet for every set-up table (`ovid_sheet_ui`, `ovid_sheet_send`; editor.R uses it in the Workbench): value bar with name box, Find and Go to date; edit in place, ranges with count/sum/mean/min/max, copy and paste, sort, Undo, Redo and Apply; cells hold values only (no formulas). Screen-only |
| `files.R` | import and export, the same in every app (core 1.10.0, the Ovid RS pattern): `ovid_browse_button()` + `ovid_browse()` give each folder box a Browse… button that opens Finder or Explorer, or an in-app folder browser (places, clickable path, filter) when neither is there. `ovid_export_button()` labels downloads "Export <what> (<FORMAT>)"; `ovid_download()` and `ovid_downloads(app)` name every file `ovid_<app>_<what>_<YYYY-MM-DD>.<ext>`. File uploads stay on Shiny's fileInput |
| `launcher.R` | the launcher behind each app's `launcher/run_app.R`, used by the Windows `.bat` files and the Mac `.command` files (private package library, first-start installs including readxl and zip, `--portable`) |

## What stays in each app

Anything whose rules differ by data type: readers, stitching, quality rules, flags (wide records flag a column, long records a value),
serial-number rules, date styles (`DT_FORMATS`), the palette (`PAL`), the set-up tables themselves (`CONFIG_FILES`) and each app's own
set-up checks. CS keeps its own `load_configs()` because its set-up tables are read differently.

## Versions

Current: core 1.14.0, shell 1.1.0, files 1.0.0. Apps: CS 1.10.0, WLR 0.10.0, GT 1.7.0, GS 0.4.0, RS 0.5.0. What changed in each version is in `CHANGELOG.md` (the core), each app's `CHANGELOG.md`, and `Ovid_Apps/CHANGELOG.md` for the whole bundle.

Bump `CORE_VERSION` (manifest.R) when a change here alters any app's output. It is written into every run manifest beside the app's version.
After a change here, run every app's tests: `Rscript tests/run_tests.R` in each app folder.
